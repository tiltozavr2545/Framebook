## Проект

Приложение для себя и пары друзей: поиск фильмов/сериалов, своя оценка,
сравнение с Кинопоиском, IMDb и другими. Автор — тот же, что у Amicus
(`~/projects/lk-system`): опыт Flutter/Riverpod/go_router уже есть, но здесь
нет сервера, и вся сложность переезжает в клиент — локальная БД, внешние API с
лимитами, синхронизация через чужое хранилище. Работать пошагово по
[docs/implementation-plan.md](docs/implementation-plan.md), не забегая вперёд.

## Ограничения среды

- **Два разработчика, две машины** — те же, что у Amicus. Android — на старом
  Intel MacBook Pro, macOS 12.7.6. Flutter новее 3.32.8 на нём не запускается
  (нужна macOS 14+), SDK закреплён на **3.32.8**. Не предлагать обновление —
  машина физически не тянет более новую macOS, это тупик. Отсюда следствие для
  зависимостей: версия пакета выбирается под Dart из Flutter 3.32.8, а не
  «последняя» — у части пакетов свежие мажоры требуют более новый SDK.
  M4 MacBook Pro без этого ограничения, но и на нём SDK тот же, чтобы
  lock-файл не расходился.
- **iOS отложен.** Целевая платформа MVP — только Android. Платформенный код
  iOS не удалять (`flutter create` его создаёт), но и не поддерживать.
- **Сервера нет и не будет в MVP.** Не предлагать «маленький бэкенд» для
  прокси ключей, кэша или синхронизации — это сознательное решение, см.
  [docs/project-brief.md](docs/project-brief.md).

## Инварианты

Правила, на которые опираются остальные решения. Нарушение любого — не
стилистика, а поломка.

- **Каталог не хранится.** Локально лежит только мини-снимок произведения
  (название, год, постер, жанры, внешние id) — ровно столько, чтобы список
  оценок открывался и сортировался без сети. Описания, актёры, полные списки
  сезонов в БД не попадают; дисковый кэш HTTP-ответов вытесняемый и
  синхронизацией не переносится. Граница — в
  [docs/data-model.md](docs/data-model.md).
- **Ключи API не попадают ни в репозиторий, ни в сборку, ни в Google Drive.**
  Они вводятся пользователем и лежат в `flutter_secure_storage`. В логах и
  отчётах об ошибках ключ маскируется.
- **Оценка хранится целым числом полубаллов** (`score_half` 2…20 = 1.0…10.0).
  Никаких `double` в БД и в файле синхронизации — сравнение «та же оценка» в
  окне калибровки обязано быть точным.
- **Ключ записи — естественный, не случайный.** `work_key` вида
  `tmdb:movie:603`, `tmdb:tv:1399:s1:e3` выводится из идентификаторов
  источника. Две офлайн-оценки одного фильма на двух устройствах — это одна
  строка с конфликтом, а не две строки-дубля.
- **Синхронизируемые строки не удаляются физически.** Удаление — это
  `deleted_at` (tombstone). Без него слияние воскрешает удалённое с другого
  устройства.
- **`updated_at` меняется на любое пользовательское изменение строки и только
  на него.** Фоновое обновление снимка или кэша рейтингов `updated_at` оценки
  не трогает — иначе оно выигрывает слияние у настоящей правки с другого
  устройства.
- **Формат файла синхронизации версионируется** (`format_version`) и читается
  с обратной совместимостью. Устройство со старой версией приложения, увидев
  файл более новой версии, синхронизацию не выполняет и просит обновиться —
  не перезаписывает файл своим урезанным представлением.

## Конвенции работы

- **Изменения локальной схемы — только миграциями drift** с увеличением
  `schemaVersion` и тестом миграции на снимке предыдущей схемы
  (`drift_dev schema dump` + `schema steps`). Ручных `ALTER` нет.
- **Версия бампается в каждом PR**: формат `name+build` в `app/pubspec.yaml`,
  `build` монотонный (это `versionCode` Android). Make-цели — как в Amicus
  (`make verify`, `make verify-version`, `make bump-*`), заводятся на Этапе 0.
- **Перед сдачей**: `make verify` (deps, формат, analyze, тесты) для `app/`.
- **Тесты на чистую логику обязательны**: слияние синхронизации, построение
  `work_key`, сопоставление id между источниками, выбор соседей для окна
  калибровки, агрегаты статистики. Это то, что не проверить глазами.
- **Внешние API в тестах не дёргаются.** Клиенты источников спрятаны за
  интерфейсами, в тестах — фейки с записанными ответами (`test/fixtures/`).
- **Локализация**: строки в `app/lib/l10n/app_{en,ru}.arb`, генерация —
  `flutter gen-l10n`, сгенерированные файлы коммитятся. Править ARB
  **текстом**: переписывание через `json.dump` съедает пустые строки, которыми
  файл разбит на смысловые группы.
- **Решения фиксировать в `docs/`**, а не только в коде: «почему» здесь
  живёт в документах (миграций с комментариями, как в Amicus, нет). Если
  решение меняется — правится документ, а не дописывается второй рядом.
- **`CLAUDE.md` — тонкая обёртка вокруг этого файла**, содержит только
  специфичные для Claude Code отличия (сейчас их нет). Общие конвенции и
  грабли живут только здесь, не дублировать.

## Грабли

Перенесено из Amicus — там это стоило реальных багов, здесь тот же стек:

- **`ref` после `await` бросает, если виджет размонтирован** — и в release
  тоже. Захватывать контейнер ДО `await`
  (`ProviderScope.containerOf(context, listen: false)`), иначе обновление
  соседних экранов молча не происходит.
- **Время — UTC на границе хранения.** В БД и в файле синхронизации — UTC
  (миллисекунды эпохи), в локальное время переводится только при
  отображении. Даты выхода из API (`release_date`, `first_air_date`) — это
  даты без времени, их в `DateTime` с часовым поясом не превращать.
- **Жест «назад» проверять только на `Navigator.push()`-экранах** — на
  экранах через `context.go()` стек пуст, и сворачивание приложения законно.

Свои:

- **«Последняя версия» пакета обычно несовместима с закреплённым SDK.**
  `flutter pub add drift_dev` к drift 2.31 не резолвится: свежий drift тянет
  `test`/`sqlite3`, требующие Dart 3.10+, а `test` прибит через
  `flutter_test` из SDK. Лечится снятием ограничения (`any`) — решатель сам
  находит потолок (drift 2.29). Подобранные версии и потолки — в
  [docs/client-architecture.md](docs/client-architecture.md).
- **Сеть на машине разработки медленная (порядка 130 КБ/с до pub.dev), и
  `flutter pub get` на ней однажды провисел 22 часа без единой ошибки** —
  загрузка архива встала посреди потока. Признак — `-v`-лог не растёт
  минутами на строке `Creating … .tar.gz from stream`. Убить и
  перезапустить; уже скачанное в `~/.pub-cache` повторно не качается.
