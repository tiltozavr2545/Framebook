# Устройство клиента

Чем собрано приложение и что в нём где. Сервера нет, поэтому здесь — вся
архитектура проекта, а не «то, что клиент делает поверх схемы», как в
Amicus. Схема данных — в [data-model.md](data-model.md), внешние API — в
[external-sources.md](external-sources.md), синхронизация — в
[sync.md](sync.md).

**Статус: каркас собран на Этапе 1** (БД, ключи, настройки, навигация).
Список ниже — решения по умолчанию; если что-то заменится по ходу (например,
drift на что-то другое), это фиксируется здесь же, чтобы документ не
расходился с кодом молча.

## Технические решения по умолчанию

- **Flutter:** 3.32.8, закреплён (ограничение машины — см. [../AGENTS.md](../AGENTS.md));
  версии пакетов подбираются под его Dart
- **State management:** Riverpod
- **Навигация:** go_router, нижняя навигация через `StatefulShellRoute`
  (вкладки: Поиск, Мои оценки, Хочу посмотреть, Статистика; настройки — из
  шапки)
- **Локальная БД:** drift (SQLite) — типизированные запросы, реактивные
  `watch()`-потоки под Riverpod, миграции с тестами на снимках схемы
- **HTTP:** dio + интерцептор кэша на диске (`dio_cache_interceptor` с
  файловым или drift-хранилищем) — TTL по типу запроса из
  [external-sources.md](external-sources.md)
- **Картинки:** cached_network_image, ключ кэша — `poster_path` и размер, а
  не полный URL (урок Amicus: ключ кэша не должен зависеть от того, что
  перевыпускается)
- **Секреты:** flutter_secure_storage (ключи API), за интерфейсом
  `KeyStorage` — в тестах подменяется памятью
- **Ссылки наружу:** url_launcher (инструкция по ключам открывается в
  браузере)
- **Настройки:** shared_preferences
- **Google:** google_sign_in + googleapis (Drive v3) +
  extension_google_sign_in_as_googleapis_auth. Встала google_sign_in 7.2.0 —
  это уже новый API (авторизация отдельно от входа через
  `authorizationClient`), примеры под 6.x к ней не подходят
- **Сериализация:** json_serializable для DTO внешних API и формата
  синхронизации; DTO API и строки БД — разные классы
- **Графики статистики:** fl_chart
- **Линтинг/форматирование:** flutter_lints + `dart format`, в CI с первого
  коммита
- **Структура репозитория:** `app/` — Flutter-проект (org
  `com.github.tiltozavr2545`, пакет `framebook`), `docs/` — документация
- **Репозиторий:** [github.com/tiltozavr2545/Framebook](https://github.com/tiltozavr2545/Framebook)

## Слои

```
lib/
  app/                  — точка входа, роутер, тема, локализация
  data/
    db/                 — drift: таблицы, DAO, миграции
    sources/
      tmdb/             — клиент и DTO TMDB
      poiskkino/        — клиент и DTO ПоискКино
      omdb/             — клиент и DTO OMDb
    ratings_service.dart — сбор внешних рейтингов: кэш → бюджет → источник
    budget.dart         — учёт лимитов (api_budget)
    work_key.dart       — сборка и разбор work_key
  sync/                 — формат файла, слияние (чистые функции), Drive-транспорт
  features/
    search/  title/  ratings/  watchlist/  stats/  settings/  onboarding/
  shared/
```

Правила:

- **Клиент источника знает только свой API** и отдаёт доменные значения, а
  не свои DTO. Решение «откуда брать IMDb — из OMDb или из ПоискКино»
  принимает `ratings_service`, а не экран.
- **Слияние синхронизации — чистые функции** над списками строк, без Drive
  и без БД. Транспорт (Drive) и применение (транзакция drift) — отдельно.
  Только так алгоритм можно тестировать на тысячах случайных
  последовательностей.
- **Экраны читают БД через `watch()`-потоки.** Синхронизация, применившая
  удалённые изменения, обновляет открытые списки без ручных `invalidate`.

## Запуск и ключи (Этап 1)

`main()` до `runApp` открывает БД (и создаёт `device_id`, если его нет),
читает `SharedPreferences` и ключи — и подставляет всё это в `ProviderScope`
через override. Причина одна: первому кадру нужны тема, язык и знание «есть
ли ключ TMDB», иначе приложение мигнёт не той темой или главным экраном
перед онбордингом.

Роутер держит человека на онбординге, пока нет ключа TMDB, и возвращает
туда, если ключ удалили. С онбординга человек уходит сам, кнопкой: после
TMDB он может захотеть добавить и необязательные ключи.

Проверка ключа — один запрос (`KeyValidator`, `lib/data/key_validator.dart`)
с четырьмя исходами: работает / работает, но лимит исчерпан / отвергнут /
не достучались. Отвергнутый не сохраняется; «не достучались» сохраняется с
пометкой «не проверен». Пробный запрос к ПоискКино и OMDb списывается из
суточного бюджета, как любой другой.

Общий HTTP-клиент (`lib/data/http.dart`) не бросает на 4xx/5xx:
`{"Error": "Invalid API key!"}` с кодом 401 — это ответ, который разбирает
клиент источника, а исключение — только сетевой сбой.

## Карточка произведения

Порядок загрузки, чтобы экран был полезен сразу:

1. Мини-снимок из `works`, если есть: название, год, постер, своя оценка —
   мгновенно и без сети.
2. Карточка TMDB (через HTTP-кэш): описание, сезоны, рейтинг TMDB.
3. Внешние рейтинги из `external_ratings`: показываются сразу, даже
   устаревшие. Параллельно, если они старше 7 суток и бюджет позволяет, —
   перезапрос.

Каждый источник рейтинга — отдельная ячейка со своим состоянием: значение /
нет данных / нет ключа / загрузка / ошибка. Падение одного источника не
ломает карточку.

## Оценка

- Ввод — ряд из 19 значений 1.0…10.0, шаг 0.5 (слайдер с фиксацией или
  сетка кнопок — решается на макете). Повторный тап по текущей оценке не
  удаляет её; удаление — отдельным действием с подтверждением.
- Сохранение — одна транзакция: `works` (снимок со всеми предками) +
  `ratings` + tombstone в `watchlist`.
- После сохранения — **окно калибровки** (bottom sheet): «Так же», «Чуть
  выше», «Чуть ниже», запросы — в [data-model.md](data-model.md). Тап по
  другой оценке в шапке окна меняет только что поставленную, и окно
  перестраивается. Окно не открывается, если других оценок этого типа нет.

## Офлайн

Без сети работает всё, что опирается на БД: оба списка, сортировки (включая
расхождение по уже закэшированным рейтингам), статистика, изменение и
удаление оценок, заметки. Поиск и открытие карточки того, чего нет в
HTTP-кэше, без сети недоступны; экран говорит об этом прямо, а не крутит
индикатор.

## Обновление, которое переживает свой экран

Правило из Amicus, тот же стек: `ref` после `await` бросает, если виджет
успел размонтироваться. Захватывать `ProviderContainer` до `await`. Здесь
это особенно касается сохранения оценки, после которого обновляются чужие
вкладки (списки, статистика). Благодаря `watch()`-потокам drift таких мест
должно быть мало — но не ноль.
