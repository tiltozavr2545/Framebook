## iOS

Отложен решением на старте: раздача друзьям сейчас только на Android.
Платформенный код iOS создаётся `flutter create` и лежит в репозитории, но
не поддерживается. Когда дойдут руки:

- сборка на M4-маке, TestFlight с аккаунта разработчика, заведённого для
  Amicus (процесс — `docs/ios-deployment-guide.md` в lk-system);
- отдельный iOS OAuth-клиент в Google Cloud и URL scheme для google_sign_in;
- ключ «Keychain» для flutter_secure_storage переживает удаление приложения —
  решить, хорошо это или плохо для ключей API.

## Импорт оценок из других сервисов

- **IMDb** — CSV-выгрузка «Your Ratings» (там есть `Const` = `imdb_id` и
  оценка 1–10): сопоставление `imdb_id → TMDB` через `/find/{imdb_id}`.
- **Letterboxd** — CSV-выгрузка, шкала 0.5–5 → ×2; id там нет, только
  название и год, то есть нужно сопоставление по названию с ручным
  подтверждением сомнительных — в противоречии с правилом «никакого
  сопоставления по названию» из [external-sources.md](external-sources.md),
  поэтому только с экраном проверки.
- **Кинопоиск** — официальной выгрузки нет; вариант — разбор сохранённой
  HTML-страницы оценок или сторонних экспортёров. Сопоставление по `kp_id`
  через ПоискКино (там есть `externalId.tmdb`), но 200 запросов в сутки
  растянут импорт большой библиотеки на дни.

Открытый вопрос: если оценка уже есть, что важнее — импорт или локальная?

## Ручная привязка внешнего id

«Это не тот фильм на Кинопоиске» — возможность вручную указать `kp_id` или
`imdb_id`, когда автоматическое сопоставление ошиблось или не нашло. Ручная
привязка должна синхронизироваться (сейчас `works` — производные данные), то
есть это изменение формата.

## Перенумерация серий в TMDB

`work_key` серии строится по номерам сезона и серии. Если TMDB
перенумерует (перенос спецвыпусков, склейка двойных эпизодов), оценка
остаётся на старом номере. Вариант: хранить TMDB id серии и при
расхождении номера предлагать перенести оценку.

## Фоновая синхронизация и обновление рейтингов

Сейчас и то и другое — только пока приложение открыто. WorkManager на
Android позволит синхронизироваться после изменений и раз в сутки
подтягивать рейтинги в пределах бюджета.

## Чистка tombstone

Сейчас хранятся вечно (см. [sync.md](sync.md)). Чистить можно только вместе
с правилом «устройство, не синхронизировавшееся дольше N дней, заменяет
локальное состояние файлом, а не сливает», иначе оно воскресит удалённое.

## Синхронизация ключей API и настроек

Чтобы на новом устройстве не вводить три ключа заново. Ключи в Drive
пользователя — это его же хранилище, но всё равно секреты вне устройства;
вариант — шифровать ключом, производным от пароля, который знает только
пользователь.

## Проверка обновлений в приложении

Запрос к GitHub Releases API при запуске: если есть версия новее —
ненавязчивая плашка со ссылкой на APK.

## Пересмотры

История нескольких просмотров с разными оценками и датами; текущая оценка —
последняя. Меняет модель: `ratings` перестаёт быть «одна строка на
произведение».

## Дата просмотра

Когда смотрел, а не когда оценил. Отдельное поле в `ratings` — изменение
формата синхронизации.

## Идеи на потом

- **Сравнение с друзьями** — обмен экспортами и «где мы с другом сильнее
  всего расходимся». Без сервера — только через файл.
- **Отдельный «свой» источник рейтингов** — например, Letterboxd, если
  появится доступный API.
- **Виджет на рабочий стол** — «Хочу посмотреть» или случайный фильм из
  списка.
- **Web/desktop-версия** — Flutter Web упрётся в CORS у части API, без
  сервера-прокси вряд ли.
